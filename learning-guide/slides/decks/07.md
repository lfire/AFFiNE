## 起步：编译到底在做什么

<p class="lead">如果只写过 JavaScript，第一道坎不是语法，而是代码怎么跑起来：Rust 必须先「翻译」成机器指令。</p>

| 步骤 | 发生了什么 | 类比 |
| --- | --- | --- |
| 1. 写源代码 | 编辑 <code>main.rs</code>，人类可读的文本 | 写菜谱 |
| 2. 编译 | <code>rustc</code> / <code>cargo</code> 翻译成机器指令，同时**检查规则** | 译成机器指令并检查配料 |
| 3. 运行 | 得到可执行文件并执行 | 机器按指令做菜 |

差别在**第 2 步**：脚本语言要运行到某一行才暴露那一行的问题；Rust 的编译器在程序跑起来之前把**整份代码**验一遍，规则不满足就拒绝生成可执行文件。

<div class="note note--tip">

本章后面的练习里，**看到编译错误是正常且必要的**，有几道题甚至要求你故意让编译器报错。读 Rust 报错是一项要练的技能，不是你写错了才有的惩罚。

</div>

## 起步：装工具链跑起来

三个名字别被绕晕：<code>rustup</code> 装/切版本、<code>rustc</code> 是编译器本体、<code>cargo</code> 是项目管家（日常只用它）。

```bash
curl --proto '=https' --tlsv1.2 -sSf https://sh.rustup.rs | sh
rustc --version
cargo new hello_rust
cd hello_rust
cargo run
```

| 命令 | 作用 | 常见的坑 |
| --- | --- | --- |
| `rustc --version` | 打印版本，确认装好 | 报 `command not found` 说明要重开终端 |
| `cargo new hello_rust` | 生成 `Cargo.toml` 与 `src/main.rs` | 项目名用小写加下划线 |
| `cd hello_rust` | 切换当前目录 | 忘了 cd，下一条会报找不到 Cargo.toml |
| `cargo run` | **先编译、再运行** | 第一次慢一点，属正常 |

屏幕上出现 `Hello, world!` 就成功了。终端里 `cd` 相当于在文件管理器里双击进入文件夹；命令必须在正确的目录下执行，这是新手最常见的挫败来源。

<div class="note note--tip">

`cargo run` = 编译 + 运行两步合成一条命令。直接双击 `main.rs` 不会执行任何代码——那只是一份源文本。

</div>

## 起步：读程序与读报错

```rust
fn main() {
    let name = "AFFiNE";
    let version = 7;
    println!("{name} v{version}");
}
```

| 行 | 含义 |
| --- | --- |
| `fn main()` | 函数；`main` 是程序入口 |
| `{` … `}` | 函数体，也圈出一段**作用域**（所有权全靠它） |
| `let name = "AFFiNE";` | 声明变量；行尾 `;` 是语句结束符 |
| `println!(…)` | 打印；末尾 `!` 表示它是**宏**不是普通函数 |
| `"{name} v{version}"` | 用 `{}` 把变量填进字符串 |

故意删掉第 3 行的分号，编译器会给出类似这样的输出：

```text
error: expected `;`, found `println`
 --> src/main.rs:2:19
  |
2 |     let version = 7
  |                   ^ help: add `;` here
```

读报错固定三步：**看 `error:` 知道问题 → 看 `-->` 定位文件和行号 → 看 `help:` 找修复建议**。另外要区分 `error`（拦住编译）与 `warning`（只提醒，仍会生成可执行文件）。

<div class="note note--tip">

有些报错带错误码（如 `E0382`），终端里敲 `rustc --explain E0382` 会打印更详细的讲解和示例。

</div>

## 起步：不可变与栈堆

```rust
fn main() {
    let count = 1;
    // count = 2;       // 编译错误：默认不可变
    let mut total = 1;  // mut = 允许修改
    total = 2;
}
```

`let` 声明的变量**默认不可变**，想改必须写 `let mut`。这不是刁难：Rust 的借用规则建立在「同一时刻要么多个只读、要么一个可写」之上，默认不可变让「只读」成为常态，编译器更容易证明安全。

| | 栈 | 堆 |
| --- | --- | --- |
| 放什么 | 大小固定（`i32`、`bool`） | 大小会变（`String`、`Vec`） |
| 复制成本 | 几乎为零 | 可能很贵 |
| 谁释放 | 随作用域自动进出 | **需要有人负责归还** |

堆内存谁归还？C/C++ 手写 `free`，JS/Java 靠 GC 定期扫描，**Rust 让编译器在编译期按规则确定释放点**。要让编译器知道「在哪释放」，就必须明确「这块内存归谁」——这正是下一节所有权的全部命题。

<div class="note note--tip">

栈 / 堆只是直觉模型，本章只需一条结论：**固定大小的值复制便宜，大小会变的值需要有人负责释放**。看到 `String`、`Vec` 就想到「它拥有一块堆内存」，后面 move / 借用 / clone 的取舍全都顺了。

</div>

===

## 三条路线，Rust 走第三条

内存到底谁来管？你熟悉前两条，Rust 另辟蹊径。

<div class="cards cols-3">
  <div class="card"><div class="card__icon">🔧</div><h4>手动管理</h4><p>C/C++ 自己 <code>malloc</code>/<code>free</code>。快，但悬垂指针、二次释放、数据竞争防不胜防。</p></div>
  <div class="card"><div class="card__icon">🗑️</div><h4>垃圾回收</h4><p>JS/Java/Go 运行时定期回收。省心，但有 GC 停顿与运行时开销。</p></div>
  <div class="card"><div class="card__icon">📐</div><h4>编译期所有权</h4><p>Rust 按规则在编译期确定释放点。既无 GC 开销，又堵住那些内存错误。</p></div>
</div>

<div class="note note--tip">

核心洞察：**"内存何时释放"在编译期可推断**——只要给"谁拥有它"定一套明确规则。检查这套规则的编译器部件叫 **borrow checker**。代码一旦编译通过，就不会有上述那类内存错误。你和它"吵架"时，本质是它在替你做证明。

</div>

## 所有权三原则

<ol class="steps">
  <li><h4>（L0）跑起来并读懂报错</h4><p><code>cargo new hello_rust</code> 后跑通；故意删一个分号，按「错误内容 → 文件行号 → help 建议」抄下报错；再加 <code>let mut n = 1; n = 2;</code> 验证 mut。<b>验收</b>：说清 <code>cargo run</code> 做了哪两步、warning 与 error 的区别。</p></li>
  <li><h4>（L2）让 move 报错再修好</h4><p><code>let s2 = s1;</code> 后用 <code>s1</code>，观察报错；再分别用 <code>clone()</code> 和传引用 <code>&s1</code> 修好。<b>验收</b>：说清两种修法的代价差异。</p></li>
  <li><h4>（L3）撞一次借用规则</h4><p>同时持有 <code>&v</code> 与 <code>&mut v</code> 并都用，记录报错；再调整顺序让只读借用先用完。<b>验收</b>：复述"共享只读 / 独占可写"。</p></li>
  <li><h4>（L4）enum + match 建模</h4><p>定义 <code>enum Event { Click{x,y}, Key(char), Close }</code>，用 <code>match</code> 穷尽处理，再故意删一个分支看报错。<b>验收</b>：解释穷尽检查为何能防 bug。</p></li>
  <li><h4>（L4）Result 与 ? 串错误</h4><p>写 <code>parse_point("3,4")</code> 用 <code>?</code> 解析两个整数。<b>验收</b>：<code>"3,4"</code> 得 <code>Ok((3,4))</code>、<code>"3,x"</code> 得 <code>Err</code>，并说清 <code>?</code> 做了什么。</p></li>
  <li><h4>（L5–L6）泛型 + 异步闭环</h4><p>写带 <code>T: PartialOrd</code> 约束的 <code>largest</code>（再删掉约束看报错），并在 <code>Cargo.toml</code> 加 tokio，用 <code>#[tokio::main]</code> 对比「不写 .await」与「写了 .await」。<b>验收</b>：说清约束为何不能删、Future 为何惰性。</p></li>
</ol>

<div class="note">

第 1、2 条解决"何时释放"，第 3 条最反直觉——下一屏专门拆解 move。

</div>

## move 语义：赋值不是拷贝

把 `String` 赋给另一个变量，所有权就"搬家"了，原变量当场失效。

<div class="compare">
  <div class="compare__col"><h4>JavaScript 的直觉</h4>

- `s2 = s1` 只是多一个引用
- 两者指向同一对象，都能用
- 由 GC 统一回收

  </div>
  <div class="compare__col compare__col--good"><h4>Rust 的 move</h4>

- `let s2 = s1;` 所有权转给 `s2`
- `s1` 立即失效，再用就报错
- 保证只有一个所有者负责释放

  </div>
</div>

```rust
let s1 = String::from("hello");
let s2 = s1;          // 所有权移动到 s2，s1 失效
// println!("{s1}");  // ❌ borrow of moved value: `s1`
println!("{s2}");     // ✅
```

<div class="note note--warn">

为什么要 move？若 `s1`、`s2` 都"有效"，作用域结束时这块堆内存会被**释放两次**（二次释放）。move 从根上杜绝了它。

</div>

===

## Copy 与 clone：两条出路

move 不是绝对的，看数据在哪、有多贵。

<div class="split">
<div class="split__main">

- **Copy 类型**：`i32`/`bool`/`char`/`f64` 等栈上定长类型，赋值<b>按位复制</b>，原变量仍可用，不发生 move。
- **clone**：想对 `String`/`Vec` 这类堆数据留一份独立副本，必须<b>显式</b> `clone()`——代价可见。

Rust 让"复制有多贵"变得显式：廉价栈拷贝悄悄发生，昂贵堆拷贝必须你亲手写。

</div>
<div class="split__aside">

```rust
let a = 5;
let b = a;           // i32 是 Copy
println!("{a} {b}"); // ✅ 5 5

let s1 = String::from("hi");
let s2 = s1.clone(); // 显式深拷贝
println!("{s1} {s2}"); // ✅ 都能用
```

</div>
</div>

<div class="note note--warn">

别把 `clone()` 当"消除编译错误的咒语"。满屏 clone 往往意味着你真正需要的是**借用**，根本不必拷贝。

</div>

===

## 借用：&T 与 &mut T

每次用值都 move 显然不现实。用 `&` 创建**引用**，临时访问而不获取所有权。

<div class="split">
<div class="split__main">

- `&T`：<b>不可变引用</b>（共享借用），只能读；
- `&mut T`：<b>可变引用</b>（独占借用），可以改。

函数借用用完，原变量依然归自己——这正是借用相对 move 的价值。方法里的 `&self` / `&mut self` 也是同一回事。

</div>
<div class="split__aside">

```rust
fn length(s: &String) -> usize { s.len() }
fn push_bang(s: &mut String) { s.push('!'); }

let mut text = String::from("hi");
let n = length(&text);  // 只读借用
push_bang(&mut text);   // 可变借用
println!("{text} {n}"); // hi! 2
```

</div>
</div>

===

## 借用规则：共享只读，或独占可写

<p class="lead">同一时间对同一个值：要么任意多个 <code>&T</code>（只读），要么唯一一个 <code>&mut T</code>（可写）——不能并存。</p>

<ol class="steps">
  <li><h4>多个只读 OK</h4><p><code>let r1 = &v; let r2 = &v;</code> 任意多个共享借用都行，因为谁都不改。</p></li>
  <li><h4>只读用完才可变</h4><p>只读借用不再使用后，才能 <code>let m = &mut v;</code> 独占可变借用并修改。</p></li>
  <li><h4>读写同时发生被拒</h4><p>同时持有 <code>&v</code> 与 <code>&mut v</code> 并都使用 → 编译失败。</p></li>
</ol>

<div class="note note--danger">

"多个读者 **或** 一个写者"正是**数据竞争**的反面。C/C++ 里两线程一读一写同一内存是未定义行为；Rust 把这条规则前移到编译期，**数据竞争在编译阶段就无法通过**——这就是"无畏并发"。

</div>

===

## 借用规则逐步看

跟着注释走一遍 `v` 的借用生命周期。

<div class="annotate">

```rust [3-4|6-7|10-11]
let mut v = vec![1, 2, 3];

let r1 = &v;             // 只读借用
let r2 = &v;             // 可以有多个只读
println!("{r1:?} {r2:?}"); // r1/r2 到此用完

let m = &mut v;          // 现在才能独占可变借用
m.push(4);
println!("{m:?}");

// let r = &v;           // ❌ 若与下一行同时存在…
// let w = &mut v;       // …cannot borrow `v` as mutable
```

<ol class="annotate__notes">
  <li><b>第 3–4 行</b>：多个 <code>&v</code> 只读共享，合法。</li>
  <li><b>第 6–7 行</b>：只读借用用完，可变借用才登场，独占修改。</li>
  <li><b>第 10–11 行</b>：读与写若同时存在就被拒——数据竞争在此被编译期挡下。</li>
</ol>
</div>

## 生命周期：引用别比数据活得久

借用引出新问题：引用指向的数据必须比引用本身活得久，否则就是悬垂引用。

<div class="split">
<div class="split__main">

生命周期（lifetime）是编译器追踪"每个引用能活多久"的机制。**大多数时候你根本不用写**，编译器自动推断（省略规则）；只在"返回引用、来源有歧义"时才需手写 `'a`。

`'a` 不延长寿命，只**描述关系**：下方 `longest` 的返回引用活得不超过 `a`、`b` 中较短者。看不懂复杂标注时先问："返回的引用借自哪个参数？"

</div>
<div class="split__aside">

```rust
let r;
{
    let x = 5;
    r = &x;  // 借用 x
}            // ❌ x 被释放
// `x` does not live long enough

fn longest<'a>(a: &'a str, b: &'a str)
    -> &'a str {
    if a.len() >= b.len() { a } else { b }
}
```

</div>
</div>

<div class="note note--tip">

<a href="../../03-编程语言与基础技术/11-Rust与NAPI-rs.md#ch-11">第 11 章</a>会在 AFFiNE 的 JSON 查询代码里见到真实的 `'a`。本屏能读懂"返回引用借自哪个入参"即可。

</div>

## struct、enum 与穷尽的 match

`struct` 聚合字段；带数据的 `enum` 对应 TS"可辨识联合"但更强；`match` **必须穷尽**所有变体，漏一个就编译不过。

<div class="split">
<div class="split__main">

```rust
struct User { id: String, active: bool }

enum Shape {
    Circle(f64),             // 携带半径
    Rect { w: f64, h: f64 }, // 具名字段
    Unit,
}
```

删掉 `Shape::Unit` 那一臂，编译器直接报 `non-exhaustive patterns: Unit not covered`——"忘记处理某情况"的 bug 溜不过去。

</div>
<div class="split__aside">

```rust
fn area(s: &Shape) -> f64 {
    match s {
        Shape::Circle(r) =>
            std::f64::consts::PI * r * r,
        Shape::Rect { w, h } => w * h,
        Shape::Unit => 0.0,
    }
}
```

</div>
</div>

<div class="note note--tip">

TS 要靠 `kind` 字段 + `switch` + `strict` 才能模拟，Rust 把它做成**语言内建、默认穷尽**——"代数数据类型比可辨识联合更强"。

</div>

===

## 错误处理：没有 null，没有异常

两个标准库 enum 把"可能出问题"写进**类型**，调用方被逼着处理。

<div class="compare">
  <div class="compare__col"><h4><code>Option&lt;T&gt;</code> 取代 null</h4>

- `Some(T)` 有值 / `None` 没有
- 调用方被类型逼着处理 `None`
- "空指针"类 bug 几乎不存在

  </div>
  <div class="compare__col compare__col--good"><h4><code>Result&lt;T, E&gt;</code> 取代异常</h4>

- `Ok(T)` 成功 / `Err(E)` 失败
- 错误是普通返回值，必须显式处理
- 不会像异常那样悄悄穿透调用栈

  </div>
</div>

```rust
fn first_char(s: &str) -> Option<char> {
    s.chars().next() // 空串返回 None
}
```

## ? 运算符：标注一段错误传播

`?` 的语义：**是 `Err` 就立刻 return 这个错误；是 `Ok` 就取出值继续**。

<div class="annotate">

```rust [3|4|5]
use std::num::ParseIntError;

fn sum_two(a: &str, b: &str) -> Result<i64, ParseIntError> {
    let x: i64 = a.parse()?; // 失败就直接 return Err
    let y: i64 = b.parse()?; // 成功就取出值继续
    Ok(x + y)
}
// sum_two("3","4")    -> Ok(7)
// sum_two("3","oops") -> Err(ParseIntError{..})
```

<ol class="annotate__notes">
  <li><b>第 3 行</b>：返回类型写明 <code>Result&lt;i64, ParseIntError&gt;</code>——一眼看出"这里会失败"。</li>
  <li><b>第 4 行</b>：<code>a.parse()?</code> 等价于 <code>match</code>：<code>Err</code> 则 <code>return Err(From::from(e))</code>，<code>Ok</code> 则取值。</li>
  <li><b>第 5 行</b>：<code>?</code> 返回时还会按 <code>From</code> <b>自动转换错误类型</b>——<a href="../../03-编程语言与基础技术/11-Rust与NAPI-rs.md#ch-11">第 11 章</a>整条错误链靠它串起。</li>
</ol>
</div>

<div class="note note--tip">

异常是"隐式控制流"，看签名不知道会抛什么。Rust 把错误写进**返回类型**保持显式，`?` 又让传播写起来和异常一样简洁。

</div>

===

## trait 与泛型

<div class="split">
<div class="split__main">

- **trait**：定义一组行为，`impl Trait for Type` 实现。类似 TS `interface`，但更灵活（可为别人的类型实现自己的 trait）。
- `#[derive(Debug, Clone)]`：让编译器<b>自动实现</b>常用 trait。
- **泛型 + 约束**：`T: PartialOrd` 表示"这个类型至少会比较大小"，函数体内才敢用 `>`。

</div>
<div class="split__aside">

```rust
fn largest<T: PartialOrd>(list: &[T]) -> &T {
    let mut biggest = &list[0];
    for item in list {
        if item > biggest { biggest = item; }
    }
    biggest
}
// largest(&vec![3,7,2,9]) -> 9
```

</div>
</div>

<div class="note note--tip">

**单态化**：Rust 泛型会为每个实际类型**生成一份专用机器码**，<b>零运行时开销</b>，和手写具体类型一样快——与"编译期检查、运行时擦除"的 TS 泛型本质不同。

</div>

## Cargo、模块与 async

<div class="cards cols-3">
  <div class="card"><div class="card__icon">📦</div><h4>Cargo + crate</h4><p>包管理 + 构建（≈<code>npm</code>+<code>tsc</code>）。crate 是编译/分发单元，依赖在 <code>Cargo.toml</code> 声明。</p></div>
  <div class="card"><div class="card__icon">🗂️</div><h4>模块</h4><p><code>mod</code> 声明、<code>pub</code> 控可见性（默认私有）、<code>use</code> 引入路径。</p></div>
  <div class="card"><div class="card__icon">⏳</div><h4>async</h4><p><code>async fn</code> 返回<b>惰性</b> Future，<code>.await</code> 才推进；需运行时驱动，AFFiNE 用 <b>tokio</b>。</p></div>
</div>

```rust
async fn fetch_user(id: u32) -> String { format!("user-{id}") }

#[tokio::main]              // 建立 tokio 运行时并驱动
async fn main() {
    let name = fetch_user(1).await; // .await 是后缀语法
    println!("{name}");
}
```

<div class="note note--warn">

与 JS 的关键区别：**Promise 一创建就执行，Rust Future 惰性、需运行时驱动**。CPU 密集同步计算别塞进 async——<a href="../../03-编程语言与基础技术/11-Rust与NAPI-rs.md#ch-11">第 11 章</a>用 `spawn_blocking` 与 napi `AsyncTask` 正是为此。

## 自测：点击揭晓答案

<details class="quiz">
<summary>Q1（L0）. 编译型语言和浏览器里直接跑的脚本，最大差别是什么？</summary>

编译型语言多了一个**编译**步骤：编译器先把整份源文本翻译成机器指令，并在运行之前检查全部规则；不通过就拒绝生成可执行文件。脚本语言要执行到某一行才暴露那一行的问题。另外 <code>cargo run</code> 替你做了「先编译、再运行」两件事。

</details>

<details class="quiz">
<summary>Q2（L0）. 读一条 rustc 报错的三步是什么？变量默认能改吗？</summary>

三步：看 <code>error:</code> 知道问题 → 看 <code>--&gt;</code> 后面的文件与行号定位 → 看 <code>help:</code> 找修复建议；并区分 error（拦住编译）与 warning（只提醒）。变量用 <code>let</code> 声明后**默认不可变**，要改必须写 <code>let mut</code>。

</details>

<details class="quiz">
<summary>Q3. Rust 没有 GC 也不用 free，靠什么保证内存安全？</summary>

靠**所有权 + 借用规则**在**编译期**检查（borrow checker）。唯一所有者、离开作用域即释放、借用遵守"多只读或单可写"。悬垂指针、二次释放、数据竞争在编译阶段就无法通过，因此既无 GC 开销也不靠手动释放。

</details>

<details class="quiz">
<summary>Q4. 什么是 move？为什么 `let s2 = s1;`（String）后 s1 不能用？</summary>

拥有堆内存的类型赋值/传参默认**转移所有权**（move），原变量失效，保证"只有一个所有者负责释放"，避免二次释放。`i32` 等 `Copy` 类型则是复制，原变量仍可用。

</details>

<details class="quiz">
<summary>Q5. 借用规则是什么？和数据竞争什么关系？</summary>

同一时间对同一值，要么多个 `&T`（只读），要么一个 `&mut T`（可写），不能并存。数据竞争正是"并发读写同一内存且至少一个写"，借用规则从编译期禁止这种组合，于是数据竞争被排除。

</details>

<details class="quiz">
<summary>Q6. 生命周期 `'a` 会改变运行行为吗？在表达什么？</summary>

不会。`'a` 只**描述引用的存活关系**供借用检查。如 `longest<'a>(a: &'a str, b: &'a str) -> &'a str` 表示返回引用不比入参中较短者活得久。多数情况编译器自动推断（省略），无需手写。

</details>
